# PhotoLibrarian 1.2.5 — Photo tools, gallery UX and metadata privacy

Stable Windows x64 update following v1.2.4.

## Photo editing and tag preservation

- Crop a photo in place or use **SAVE AS** to export a separate image in a selected folder and format (JPEG, PNG, TIFF, BMP).
- For exported crops, explicitly choose whether to **KEEP TAGS**, export **WITHOUT TAGS** or **CANCEL**. In-place crop preserves assigned tags; exported images written inside the album are registered with the selected tag set.
- Rotate the displayed image **90° left or right**, saving the change and refreshing the viewer and thumbnails. The original photo is backed up before a destructive rotation.
- **Make Copy for Editing** preserves the source album's assigned tags, including cases where the source uses an XMP fallback.

## Gallery navigation and sorting

- Replace the old advanced gallery Filter menu with a quick, case-insensitive **filename SEARCH**. Hierarchical tag filters remain in the TAGS navigation.
- Add **Folder → File Name** sorting: order by folder path first and then filename within each folder, in either direction. Existing sorts remain available.
- Remove the unused GROUP selector and keep the flat, virtualized gallery.
- Returning from photo viewing scrolls to the last viewed photo; its selected thumbnail has a stronger cyan frame, corner indicators and SELECTED label.
- Fix initial thumbnail loading in a non-maximized window and maintain consistent gallery toolbar sizes.

## Cinematic interface

- Reuse the framed cyan progress indicator from the startup screen throughout indexing, imports, album maintenance, updates, face review and thumbnail loading.
- Align the catalog tag management CANCEL button with the shared neutral/secondary style.
- Use cinematic confirmation dialogs for thumbnail cache clearing, update download/installation and other destructive operations.

## New: metadata anonymization

- **Anonymize photo metadata…** from the gallery context menu, for a single photo or selection.
- **ALBUM // ANONYMIZE METADATA** from Settings, with explicit confirmation, per-file progress, cancellation, optional retained backups and a result report.
- For successfully processed files, strip applicable **EXIF, IPTC, XMP, GPS, camera, date, rating, keyword and comment metadata**; remove the corresponding XMP sidecars; clear photo-level tags, flags and face/person annotations in the active album cache.
- JPEG, PNG and WebP are stripped without recompressing image payloads when possible; orientation-bearing JPEG/PNG and single-frame TIFF/BMP may require re-encoding.
- RAW/DNG, HEIC/AVIF, GIF, video, unsupported or potentially unsafe multi-frame/animated formats are **skipped or reported as failed**, not silently declared anonymized.
- Existing backups and OS caches are not erased. Retained originals and sidecars under `.album/privacy-backups/` **still contain their original private metadata**. File names, folder names, timestamps and identifiable content visible inside the image are not anonymized. This is **not forensic secure deletion**.
- An interrupted or partially unsuccessful album operation is explicitly reported as **partial**. Test anonymization on a copy of a small album before using it on important photographs.

## Verification and precautions

- Windows CI application build and automated tests passed on the merged development changes.
- Manual verification is recommended for real-world EXIF orientation, mixed RAW/JPEG sidecars, color profiles, image quality and backup recovery.
- Metadata-sensitive editing and anonymization change original files. Keep independent backups before processing valuable albums.
