# PhotoLibrarian 1.2.4 — Cinematic UI visual refresh (development)

Experimental Windows x64 prerelease, following stable **v1.2.3**. Development tags use sequential `v1.2.4-dev.N` numbering. This build is **not a stable release**.

## Visual changes

- Introduce shared flat industrial styles for controls in the left image-viewer rail, both in normal viewing and fullscreen.
- Emphasize the Delete command separately with a danger accent, without changing its operation or confirmation behavior.
- Remove the obsolete decorative B02 marker from the TAGS heading.

## Broad visual consistency pass

- Harmonize global header, status bar, navigation, photo viewport, gallery toolbar and settings surfaces with a darker blue-black industrial palette and more legible cyan accents.
- Introduce reusable cinematic panel-heading and compact system-caption styles; apply them to library, tag filtering, image gallery, metadata and settings headings.
- Use consistent flat edged action buttons in the navigation and gallery, matching normal/fullscreen viewer rails.
- Improve separation and contrast of the library/metadata frame borders without changing their dimensions.
- Harmonize crop toolbar background and button edges with the rest of the workspace.
- All changes are confined to XAML presentation; no photo/tagging/indexing commands, layout dimensions or virtualization mechanics are modified.

## Final visual unification

- Add consistent contrast and typography tokens for module headings, secondary captions and neutral actions.
- Give include (+) and exclude (−) tag-filter controls distinct cyan/amber roles, without changing click semantics, filter selection or tree hierarchy.
- Style the image-straightening fine-tune panel in the same cinematic language (heading, readout, button and surface).
- Normalize album metadata labels, caption/tag headings, settings controls and the configuration footer.
- Align panel/input surface transparency and flat corner radii. Preserve existing control templates, keyboard focus behavior, interactive photo area and performance-sensitive virtualization.
- Reconcile the branch with the stable v1.2.3 release history and retain separate stable/dev release notes.

## Final screen coverage and regression checks

- Align the standalone image editor with the same panel, heading, slider-label and command hierarchy as the main viewer, without changing editing calculations.
- Style album folder management: list border, add/remove actions, database maintenance warning and section labels.
- Harmonize the people/face review workspace and photo context panel while preserving face drag-and-drop, keyboard accelerators and virtualized face thumbnails.
- Refresh the startup/boot screen palette to match the current industrial blues, cyan and warning red.
- Add offline tests for valid XAML on all Cinematic UI screens, missing shared HiTech resources, and keeping 100% zoom actions distinct from the live zoom badge.

## Dialog centering and control consistency

- Center cinematic WARNING / ERROR / FATAL and other dialog variants inside their XAML window rather than leaving the dialog near a screen edge. Constrain inner content to the dialog with a scrollable viewport for smaller windows.
- Prevent WinUI's default blue accent from overriding the safe CANCEL button of cinematic confirmations; cancellation now uses a neutral dark industrial style. Keep destructive confirmation as an explicit choice.
- Introduce shared centered dialog styling for ordinary confirmation, rename, tag-management, people review and error dialogs. Destructive actions have a separate warning/danger button treatment.
- Align the standalone folder-management dialog and Settings' visual-only dialog previews.
- Replace remaining default WinUI button treatments in the grid filter flyout, crop toolbar, manual face tagging flyout, date/time and tagging metadata actions; retain existing handlers.
- Add regression coverage for centered dialogs, shared styles and XAML integrity.

## Native dialog placement regression fix

- Restore WinUI's own popup presenter centering: remove fixed Width/MaxWidth and manual Center alignment from the ContentDialog control itself.
- Keep cinematic panel width on its content and override only ContentDialog template width resources, avoiding the WinUI dialog placement bug with constrained dialog controls.
- Remove manually assigned alignment from ordinary ContentDialogs and the folder-management dialog, which now also uses a native template width override.
- Add static regression tests preventing fixed dialog widths/incorrect control alignment. Validate actual placement visually on Windows after the development release.

## Operational dialog taxonomy

- Use the full Cinematic WARNING presentation when clearing photo tags, deleting a named person, clearing the local cache database and performing album-wide destructive maintenance.
- Route failed image renames, failed album opens, failures in people review and cache-reset failures to the Cinematic ERROR presentation.
- Route album handoff failures and album termination failures to the FATAL ERROR presentation.
- Show PROCESS COMPLETE when the database has been cleared successfully, prior to its existing application restart, and after successful long-running JPEG conversion or album metadata reset.
- Show ERROR after partial JPEG conversion / album reset (with failure counts and existing saved report), or when those operations fail unexpectedly. Preserve their progress bars, cancellation behavior and detailed status text.
- Keep simple rename/tag/input workflows in compact, centered and consistently styled dialogs, including a neutral Cancel action.
- Error and completion alerts without a confirmation action use a meaningful acknowledgement/Close label instead of Cancel.
- Keep standalone PROCESSING and INFORMATION specimens in the safe UI SHOWCASE. Existing in-workspace progress/status updates remain non-modal, avoiding interruption of long-running photo operations.
- Add regression checks for dialog variant routing and preserve existing cancellation, validation and action-handling paths.

## Preserved behavior

- Retain the photo-first widescreen layout, fullscreen overlay controls, gallery grouping, tag tree and metadata handling established in stable v1.2.3.
- No changes to photo processing, tag semantics, thumbnail virtualization or image viewer zoom behavior.
- The **100%** button sets actual image size; the actual zoom indicator remains at the lower-right corner of the photo.

## Validation

- Windows CI builds the application and runs automated tests; interactive verification is required for side-rail focus, hover, disabled and fullscreen states.
- Enable **Include development updates** in Settings only when deliberately testing prerelease versions.
