# PhotoLibrarian 1.2.1 — Trimenor

Stable Windows x64 maintenance release following **1.2.0**.

## Faster repeat of album tag cleanup

- Add **RETRY FAILED ONLY** beside the full album cleanup command in Settings.
- After a completed cleanup, save the **file paths that actually failed** in the active album's portable `.album/metadata-reset-pending.json`. Successful photos are excluded from the next targeted retry.
- Retrying previously failed images skips recursive filesystem scanning and full image indexing. Each remaining photo still uses the existing strict metadata verification, temporary rollback safeguards, and the selected backup policy.
- After each completed retry, update the list to include only files still failing. An empty completion marker prevents obsolete error reports from being mistakenly retried.
- For albums first cleaned using **1.2.0**, allow a one-time fallback to the most recent `reset-errors.txt` when no checkpoint exists.
- Preserve the full-album cleanup option for a comprehensive scan after adding or modifying photos. Only an error-free cleanup clears the album's saved tag catalog.

## Validation and limitations

- Windows CI and regression tests verify recovery from partial failure, targeted retry, and importing a legacy error report.
- Targeted retry is **not** a substitute for a full scan: files newly added or changed after the earlier cleanup will not be examined.
- The ordinary photo context-menu **Clear all tags** action is unchanged; it is not a fully verified replacement for the album-maintenance operation.
- Keep original backups when cleaning important albums, particularly across NAS/network drives.

To install after publishing, use **Settings → CHECK FOR UPDATES** or the official Windows x64 installer. The existing Inno Setup updater will keep the previously selected installation options (including the optional Windows Explorer context menu).
