# PhotoLibrarian 1.2.3 — Cinematic UI 2.0 development preview

Experimental Windows x64 prerelease. The development workflow publishes sequential `v1.2.3-dev.N` tags. This is **not** a stable release.

## Widescreen layout / PDF review 1

- Reduced empty left padding around the LIBRARY and TAGS trees, tightened tag row gaps and +/- action widths, keeping actual tree structure and selection logic intact.
- Added a floating 48 px fullscreen action rail on the left. Unlike the standard side rail, it overlays the image and does not reserve any photo viewport width.
- Reused existing handlers for Zoom Out, Fit, 100% actual size, Zoom In, Fullscreen, Delete, Back, and crop. The zoom percentage indicator remains bottom-right on the photo.
- Crop initiated from fullscreen first leaves fullscreen so the aspect / Apply / Cancel ribbon remains accessible. Manual face tagging disables conflicting actions.
- Layout-only change: no new visual theme or photo processing logic.

## Photo-first layout / PDF review 0

- Removed the redundant **BROWSE** and navigation heading, moving Open Album and Refresh into the existing **LIBRARY** header.
- Removed the **All Photos** header and its reserved 50 px when GROUP is set to None. Real grouped views keep their group headings.
- Moved the visible filtered photo count into the existing **VISUAL INDEX** toolbar.
- Moved the viewer top-bar actions (Zoom Out, Fit, **100% actual-size command**, Zoom In, Fullscreen, Delete, and Cancel Face Tagging) to the existing left system rail, alongside Crop and Back to Gallery.
- Preserved the **actual zoom indicator at the lower right of the image**. The 100% button is not a zoom-status indicator.
- Moved image filename and image position into the existing global header. Removed the separate viewer top bar without introducing another permanent horizontal row.
- Kept the original command handlers, image zoom/pan, fullscreen, data operations and tag logic in place.
- This iteration is focused only on **layout**, not visual redesign. Manual viewer and grouping smoke tests are still needed.

## Widescreen workspace improvements

- Reduced the persistent global header from 66 to 48 px and the bottom system bar from 42 to 32 px.
- Added compact Crop and Back-to-gallery actions to the existing 48 px left system rail while viewing an image.
- The horizontal viewer ribbon is now displayed only in crop mode, where aspect ratio and Apply/Cancel need it.
- Reduced vertical margins around the side panels and photo viewport from 10 to 4 px.
- Kept thumbnail virtualization, gallery sorting, filters, tagging logic and fullscreen behavior unchanged.
- Viewer and crop behavior need interactive Windows checking across image and video files, including exit from fullscreen.

## Latest development changes (after dev.2)

- Expanded the Cinematic UI Showcase to six severity types: FATAL ERROR, ERROR, WARNING, PROCESS COMPLETE, INFORMATION and PROCESSING.
- Replaced the default blue Showcase footer buttons with severity-colored industrial controls.
- Added shared cinematic presentation for album maintenance confirmations (JPEG conversion and tag reset), and album deletion confirmation and fatal deletion failure. The existing actions, backup options and explicit cancellation gates are preserved.
- Added scrolling for lengthy warnings on smaller displays; all example counters and static progress are clearly labeled as previews.

## Earlier changes

- Added **Settings → SYSTEM // UI SHOWCASE**, accessible from the Settings navigation.
- Added isolated design previews for **FATAL ERROR**, **WARNING** and **PROCESS COMPLETE**, featuring large industrial panels, prominent severity typography, icons, and colored status rails.
- Added a **PREVIEW CINEMATIC SEQUENCE** action to inspect the three concepts in order.
- Kept the existing **PREVIEW ALL DIALOGS** style audit.

## Safety and scope

- The new Showcase is strictly visual: none of the preview actions changes albums, tags, files or metadata.
- Gallery/tagging implementation remains unchanged. Production album confirmations now use the shared cinematic presentation, without changing the underlying operations.
- Dialog geometry, scaling, accessibility and animations are still under design review; this build is for visual feedback, not final UI approval.

## Validation

- Windows CI builds the application and executes automated tests.
- Actual visual appearance and layout on Windows must be checked interactively.

## Development channel

Development updates are opt-in from **Settings → SYSTEM // UPDATE CONTROL → INCLUDE DEVELOPMENT UPDATES**. Stable updates and the `master` branch remain independent.
