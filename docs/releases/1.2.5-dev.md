# PhotoLibrarian 1.2.5 — photo tools and gallery search (development)

Prerelease following stable 1.2.4. Not yet approved for stable master.

## Crop: save as
- The crop toolbar now offers SAVE AS beside the original destructive APPLY and CANCEL controls.
- Windows App SDK Save dialog opens in the current photo's folder by default and still lets the user choose path, filename and output format (JPG, PNG, TIFF, BMP).
- The exported image is written atomically to a temporary sibling file before replacement of the chosen target. Original image and XMP remain unchanged.
- An exported crop is an independent picture: the user chooses whether to copy original tags. Face regions are not copied.

## Crop tag inheritance
- SAVE AS now asks whether the independent new crop should copy all assigned tag paths from the source, omit all tags, or cancel before opening the Windows Save dialog. The KEEP TAGS option is disabled when the source has no tags.
- Source tags are read from the active album database first, including paths that could not previously be written into photo metadata.
- Copied tags are written into the exported image (or its portable XMP sidecar fallback) before the output replaces the selected target. Existing independent XMP sidecars block ambiguous overwrites.
- When the saved crop is inside the active album, its SQLite tag assignments are reconciled to the chosen set. Outside the album, tags travel with the exported file/sidecar without adding a catalog entry.
- APPLY CROP now reapplies the source's assigned tags to the replacement image before committing the edit, fixing an existing risk of losing embedded keywords.
- The metadata reader also imports keywords from portable XMP sidecars when present, so later scans can recover tags written through fallback.
- Faces/person regions are deliberately NOT copied to a separate cropped image; in-place crop continues to remap faces as before.
- MAKE COPY FOR EDITING also reapplies the album's authoritative tag paths to the new copy, preserving tags even when the original used an XMP fallback.

## Rotate and save
- Two buttons in both normal and fullscreen viewer rails use distinct directional rotation icons to rotate the currently open photo 90° left or right and save it.
- The original is backed up using the album's existing backup service before the pixel rotation.
- If updating face XMP/sidecar metadata fails after rotation, the metadata transaction is rolled back and the previous photo is restored from backup.
- The viewer, dimensions and thumbnail cache are refreshed after the operation.
- Only formats supported by the existing editor are enabled (JPG, PNG, TIFF, BMP); video is excluded.
- Face-detection and embedded/sidecar geometry on rotated images require manual validation before promotion to stable.

## Gallery workflow
- Remove the GROUP selector from the toolbar and use the existing flat, sorted virtualized gallery.
- Keep SORT with File Name, Date Taken, Date Modified and File Size.
- Replace the advanced tag/media/extension Filter flyout with simple case-insensitive filename search (SEARCH / clear / Enter).
- Existing tag filtering remains available from the hierarchical TAGS navigation at left.
- SORT, SEARCH, CLEAR and thumbnail zoom controls now share consistent 34px toolbar height, button styling and icon proportions.
- Returning from the photo viewer now retains the last-viewed photo as the selection and centers its thumbnail after the gallery has a valid virtual scroll extent, even if its initial layout is still pending.
- Selected thumbnails now have a stronger cyan 3px outline, enlarged corner brackets, a continuous accent stripe above the filename, and a more prominent SELECTED indicator.

## Shared cinematic progress bars
- The startup splash screen's original framed cyan progress strip is now a shared WinUI component, used by the splash itself, the main status rail, album gallery thumbnails and empty/indexing state, the people/face review, and settings operations.
- Numeric operations retain their actual 0–100 progress; indexing, face thumbnails and other non-measurable operations use the same strip in indeterminate mode.
- Redundant circular spinners beside DigiKam/Stash imports are removed; their dedicated numerical progress bars remain.
- The catalog-tag management dialog's CANCEL button uses the shared cinematic secondary style.

## Settings and updater confirmations
- CLEAR THUMBNAILS first opens the existing cinematic WARNING dialog with the affected cache size and location; the cache is deleted only after explicit confirmation. Cancel/Escape changes nothing. Original photos, tags and album metadata remain untouched.
- Update prompts now use the existing centered cinematic dialog system instead of the legacy settings-page overlay. The download step uses INFORMATION for stable versions and WARNING for prereleases; the verified-install-and-restart step uses WARNING.
- Native dialog cancellation and settings closure safely dismiss pending update confirmation; the existing SHA-256 verification, update helper and restart workflow are unchanged.

## Verification
- Automated WinUI application build, existing tests and new filename search tests.
- Manual tests needed for save-dialog path selection, EXIF orientation in quarter-turn rotation, backups, metadata consistency and gallery search behavior.
